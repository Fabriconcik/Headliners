# Headliners — «Срочно в номер!»

Локальная вечеринка-игра для 4–10 человек: каждый играет со своего телефона, все вместе
делают хаотичный прямой эфир новостей, а в конце смотрят его ускоренный повтор.

Стек: **Node.js + Express 5 + `ws`** на сервере, **React 19 + Vite + HTML5 Canvas** на клиенте,
общие типы и константы в `shared/`.

---

## Быстрый старт

### Вариант 1. Запуск в 1 клик на Windows (без команд и без терминала)
- Дважды кликните по файлу **`start.bat`** в корне проекта (или по ярлыку на рабочем столе через **`create-desktop-shortcut.bat`**).
- Или в VS Code нажмите **`Ctrl + Shift + B`**.
- Скрипт автоматически проверит зависимости и сборку, запустит сервер и откроет игру в браузере (`http://localhost:3000`).
- Полностью защищён от ошибок PowerShell (`PSSecurityException`).

> Если вы хотите использовать терминал PowerShell, но видите ошибку `PSSecurityException`, запустите один раз файл **`fix-powershell.bat`** или пишите в терминале `npm.cmd start`.

### Вариант 2. Игра вообще без ПК (в облаке Render / Railway / Fly)
Подробная инструкция в файле [HOW_TO_PLAY_NO_PC.md](file:///c:/Users/Blinchik/Documents/VScodePrograms/Headliners/HOW_TO_PLAY_NO_PC.md):
- Бесплатный деплой на **Render.com** (файл конфигурации `render.yaml` уже настроен).
- Любой планшет, телефон или телевизор может быть хостом по ссылке вида `https://ваша-игра.onrender.com`.
- Никакой ПК не требуется!

### Вариант 3. Ручной запуск через терминал (разработка)

```bash
npm install          # один раз
npm run dev          # сервер :3000 + Vite :5173 (с проксированием /api и /ws)
```

Открыть на ноутбуке `http://localhost:5173`. На телефонах в dev-режиме открывайте
`http://<ip-ноутбука>:5173` (Vite слушает `0.0.0.0` и проксирует WebSocket на :3000).
Чтобы QR-код и адреса из лобби тоже вели на Vite, запускайте сервер с `CLIENT_PORT=5173`.

Продакшн-сборка:

```bash
npm run build        # собирает dist/client (Vite) и dist/server (tsc)
npm start            # Node-сервер раздаёт dist/client и WebSocket на одном порту
```

Переменные окружения: `PORT` (по умолчанию `3000`) и `CLIENT_PORT` — порт, который видят
игроки в ссылках/QR (по умолчанию равен `PORT`; задайте, если перед сервером стоит прокси).
В dev-режиме имеет смысл `CLIENT_PORT=5173` (PowerShell: `$env:CLIENT_PORT=5173; npm run dev`),
тогда QR и адреса из лобби будут вести на Vite. Порт прокидывается и в Vite-прокси.

## Игровой цикл

1. **Лобби** — игроки подключаются по 4-значному коду, хост может добавить ботов и включить тест-режим.
2. **Распределение ролей (15 с)** — сценаристы, художники (не больше 4), зрители-саботажники с классами.
3. **Сюжеты** — `max(3, numWriters)` раундов. В каждом:
   - `PREP` до 30 с (вне эфирного таймера): ведущий сценарист пишет заголовок, кнопка «В эфир!» выходит досрочно;
   - `SPLASH` 3 с: полноэкранная заставка с заголовком;
   - `LIVE` 45 с: художники рисуют, сценаристы сыпят фактами в бегущую строку, саботажники тратят энергию;
   - `FREEZE` 3 с: стоп-кадр и закрытие лога раунда.
4. **Повтор** — все раунды склеиваются в один таймлайн; пики реакций/саботажа идут на `1.0x`,
   остальное — на `2.5x–3.5x`. Для трёх раундов (штатный размер комнаты) хронометраж укладывается
   в 40–55 с; на тест-режимных матчах с 4+ сценаристами повтор растёт адаптивно, чтобы не разгоняться
   до немотрибельных 5x–30x.
5. **Возврат в лобби** — роли сбрасываются, можно играть следующий выпуск.

## Тесты

```bash
npm test             # node:test + tsx: tests/**/*.test.ts
npm run typecheck    # tsc для клиента и сервера
```

- `tests/*.test.ts` — юнит- и adversarial-проверки фазовой машины, ролей, эмодзи, replay-математики.
- `tests/e2e/tier1..4` — сквозные сценарии через `TestHarness` (in-memory WebSocket).
- `tests/fixes.test.ts` — регрессии на reconnect, лимиты ввода и `LEAVE_ROOM`.

## Текущее состояние

- Серверная логика, протокол, рендер-движок, сетевой слой, звук и клиентские экраны (Milestone 4: `LobbyScreen`, `RoleSelectScreen`, `BroadcastScreen`, `ReplayScreen`) полностью реализованы и покрыты тестами.
- Продакшн-сборка `npm run build` собирает клиент (`dist/client`) и сервер (`dist/server`).

### Принятые ограничения

- Комнаты живут в памяти процесса: после рестарта сервера сессии теряются (клиент пересоздаёт комнату).
- Код комнаты — 4 цифры, без авторизации: игра рассчитана на доверенную локальную сеть.
- Контент сегмента ограничен (`LIMITS` в `shared/constants.ts`): 500 элементов, 20 000 точек,
  64 КБ на сообщение — чтобы повтор и снапшоты оставались лёгкими.
